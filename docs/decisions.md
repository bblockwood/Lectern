# Decisions

Record of spec ambiguities and how they were resolved. Newest at the bottom.

| Date | Topic | Decision | Status |
|---|---|---|---|
| 2026-10-25 | Deployment targets | macOS 26.0, iOS/iPadOS 26.0, watchOS 26.0: the installed Simulator runtimes are 26.5 and the spec allows raising freely. | Fable, provisional |
| 2026-10-25 | Bundle identifier prefix | `dev.lectern` (spikes use `dev.lectern.spike.*`). Ben can change it once signing is set up; nothing depends on it. | Fable, provisional |
| 2026-10-25 | Spike projects | Each spike is a self-contained XcodeGen project or SwiftPM package under `Spikes/`, not a target of the main project, so M0 code can be deleted without touching `project.yml`. | Fable |
| 2026-10-25 | Frame grouping in second-screen-notes decks | Beamer's page labels equal frame numbers in ordinary decks (verified on `overlays.pdf`) but **not** when `show notes on second screen` is used (`notes-right.pdf`: 5 frames, labels 1,1,2,2,3,3). M3 needs a different grouping signal for notes-split decks. Options to evaluate then: the frame number printed on the slide, beamer's `Navigation<n>` named destinations, or treating each page as its own frame. | Open, for M3 |
| 2026-10-25 | Render engine | `CGContext.drawPDFPage` is fast enough (≤ 18 ms at 4K on the heaviest fixture, ~3 ms typical) and skips annotations by construction. No PDFium evaluation unless real decks show fidelity bugs. See `docs/spikes/C-render.md`. | Fable |
| 2026-10-25 | Concurrent rendering | `RenderCache` serialises renders on one `CGPDFDocument`. The spike showed 4× scaling from sharing the document across threads without crashing, but Apple does not document that as safe, and serial rendering is fast enough. Revisit only if M1 profiling shows queueing. | Fable |
| 2026-10-25 | PresenterCore imports | PresenterCore also imports `os` (for `os_log`/`os_signpost`, which CLAUDE.md asks for) and the repo's own `PresenterProtocol`, which defines `Command` so remotes and the core share one type. No UI frameworks. | Fable |
| 2026-10-25 | Mac app sandbox | Not sandboxed in M1 (hardened runtime on). Live reload needs to watch the deck's directory and read `.pdfpc`/`.pptx` siblings (§6.6, §5.1), which the sandbox makes awkward; personal/TestFlight distribution does not require it. Revisit for the App Store in M10. | Fable, provisional |
| 2026-10-25 | Cache eviction policy | `ImageStore` evicts the entry farthest from the focus pages (committed, presenter, back target) first and least-recently-used among equals, instead of pure LRU: in the self-test LRU evicted the page the presenter was about to go back to. Mac budget 768 MB (`-cacheMB=` to override); iPad will use less. | Fable |
| 2026-10-25 | Pace thresholds (§6.7) | Behind by up to 60 s is green, up to 180 s amber, beyond that red, computed as (elapsed/target − framesDone/framesTotal) × target. Section targets (M6) will refine this. | Fable, provisional |
| 2026-10-25 | Key handling | One `NSEvent` local monitor feeds `KeyMap` for every window, so clicker keys work regardless of which window is key, and the audience window never becomes key. Unmodified single-key shortcuts are therefore not menu key equivalents; menu titles show them. Text fields (M2 jump field, M3 notes editor) bypass the map. | Fable |
| 2026-10-25 | Latency measurement | `-selftest` reports input → event receipt → command applied → layer contents swapped, plus the first display-link vsync after the swap as an on-glass upper bound. The render server's compositing stage is not observable from the app; the built-in ProMotion panel also idles at low refresh rates, so only a fixed-rate external display gives a clean "one refresh" number. | Fable |
| 2026-10-25 | Focus prompt | The one-time "enable a Focus" prompt from §6.1 is deferred to M10. | Fable, provisional |
| 2026-10-25 | Overview selection granularity | Arrow keys and clicks in the overview browse to the **first** page of a frame (unbuilt), while thumbnails show the frame's last page as §4.1 asks. Committing then presents the frame from its first build. | Fable, provisional |
| 2026-10-25 | GoForward | Beamer's navigation bar emits the GoForward named action; the session keeps a `forwardHistory` stack (filled by `back`, cleared by any new jump) so it works. No key is bound to it. | Fable |
| 2026-10-25 | URI links | Ignored with a two-second notice. `defaults write dev.lectern.mac LecternOpenURILinks -bool YES` enables opening them after a confirmation dialog on the presenter Mac (SPEC §4.3, §13 open question). | Fable, provisional |
| 2026-10-25 | Thumbnail cache | A second `RenderCache` with a 96 MB budget renders the last page of each frame at up to 640×360; the overview re-requests on demand after eviction. | Fable |
| 2026-10-25 | `.pdfpc` numbering | JSON `endSlide` and `savedSlide` are 0-based user-slide indices (pdfpc keeps all slide numbering 0-based internally; only the XMP path subtracts 1), `duration` is minutes, legacy `[end_user_slide]` and `### N` are 1-based. Verified in pdfpc's `pdf.vala`. | Fable |
| 2026-10-25 | Second-screen split confirmation | The aspect heuristic (> 2.3 wide or < 0.95 tall, with pdfpc's NotesPosition as a hint) only *asks*; nothing is cropped until the user answers, and the answer lives in the sidecar. A portrait deck therefore gets one question and then is left alone. | Fable |
| 2026-10-25 | PowerPoint notes without a dependency | A minimal ZIP reader (central directory, stored and deflate via `NSData.decompressed(using: .zlib)`) and `XMLParser` read the `.pptx`; no third-party archive library. Count mismatch shows a warning and maps nothing, per §5.1.5. | Fable |
| 2026-10-25 | Live reload mechanism | Directory DispatchSource (atomic replaces), file DispatchSource re-armed after renames (in-place writes), plus a 2 s stat poll as a safety net for volumes without file events (iCloud Drive, network shares). | Fable |
| 2026-10-25 | Last position restore | Opening a deck restores the sidecar's last position (committed page) without pushing history. | Fable, provisional |
| 2026-10-25 | Ephemeral ink lifetime | 3 s (SPEC default), fading over the last second; pruned by a 100 ms tick that runs only while strokes exist. | Fable |
| 2026-10-26 | Render engine, corrected numbers | Spike C and M1 drew pages at native size (`CGPDFPageGetDrawingTransform` never scales up), so the "≤ 18 ms at 4K" figure above was wrong: the heaviest fixture page is 284 ms at 4K and 73 ms at 1080p; ordinary pages are unchanged (≤ 5 ms). The decision stands: prefetch plus keep-the-old-image covers single-step navigation (self-test on `tikz-heavy.pdf`: no misses). Concurrent rendering of heavy pages is the first optimisation to try if Ben's real decks need it. | Fable |
| 2026-10-26 | Settings window pulled forward from M10 | Ben asked for a settings interface in his first-use feedback, so a small SwiftUI Settings window (⌘,) exists now: back-navigation option, hold-⌘ overlay on/off, notes size, web links. App-wide values stay in UserDefaults; per-deck values stay in the sidecar (SPEC §3.4). | Ben |
| 2026-10-26 | ← landing on the previous frame's first build (option) | Ben: "when going back beyond the current slide, the interface jumps to the first build of each frame rather than reversing individually through them". Read as: inside a frame ← still steps one build back; at a frame's first build ← lands on the previous frame's *first* build instead of its last. Off by default (SPEC §3.2 behaviour), `NavigationOptions.previousLandsOnFrameStart`. ⇧← is unchanged. If Ben meant ← to skip builds inside the current frame too, that is a one-line change in the reducer. | Fable, provisional |
| 2026-10-26 | Red close button closes the deck, not the app | With a deck open, the presenter window's close button (and ⌘W) returns to the welcome screen; closing the welcome screen quits. Ben's feedback: "when closing project, main screen with file picker should auto-return". | Ben |
| 2026-10-26 | Pointer and draw modes are called Laser and Pen in the UI | Ben's words; the commands, menu items and keys (L, D, E) are unchanged. Buttons under the current slide mirror and toggle the modes. | Ben |
| 2026-10-27 | Clear is C, not E; labels lead with their key | Ben: "give things semantic labels that match their shortcuts". Buttons, menu items and the shortcut card say Laser (L), Draw (D), Clear (C); E is unbound. SPEC §6.5 updated. | Ben |
| 2026-10-27 | Shortcut card toggles on a ⌘ tap | A press and release of ⌘ with no key or click in between shows the card; it stays until ⌘ is tapped again, Esc is pressed, a row is clicked (which runs that command) or the backdrop is clicked. Other keys still work while it is up and leave it up, since Ben listed only those three ways to close it. ⌘-shortcuts and ⌘-clicks never show it. | Ben; keys-leave-it-up is Fable, provisional |
| 2026-10-27 | "." stays bound to black screen, the card lists only B | Clickers send "." for blank (SPEC §6.5), so the key keeps working; Ben found the "." in the card puzzling, so it is not listed. | Fable, provisional |
| 2026-10-27 | Click on the current or next slide = next build | Links still follow and draw mode still draws; everything else is a plain click. The audience window is unchanged. | Ben |
| 2026-10-27 | Countdown replaces the elapsed time | With a target set (pdfpc duration, sidecar, the Countdown menu or the editor that opens on clicking the timer), the time left takes the elapsed time's place: green while positive, red and counting up in magnitude once exhausted. Elapsed time is not shown then. SPEC §6.7's amber frames-vs-time pace is not shown for now; `PaceIndicator` stays in PresenterCore. SPEC §6.2 and §6.7 updated. | Ben; amber drop is Fable, provisional |
| 2026-10-27 | "X left" removed from the status bar | Ben did not want the main-talk-frames-left count after the build count. | Ben |
| 2026-10-27 | ⌃⌘F toggles full screen | View ▸ Enter Full Screen with AppKit's own `toggleFullScreen:`; the presenter window is `fullScreenPrimary`, so the green button works too. | Ben |
| 2026-10-27 | Notes pane doubles as the table of contents | Notes / Contents headings in the pane; Contents shows the outline with the entry containing the current page highlighted, kept in view, with each entry's frame label; clicking jumps (⌫ returns). A frame without notes shows the contents on its own; the explicit choice persists per device. The overview's outline sidebar shares the list and now highlights the *containing* entry rather than only an entry starting on the current page. | Ben; fallback rule is Fable, provisional |
| 2026-10-27 | Transitions dropped | Ben: "let's remove them for now". Nothing was implemented (they were M9); SPEC §4.5 and the §13 open decision are struck. pdfpc's `DefaultTransition` metadata is still parsed and ignored. | Ben |
| 2026-10-27 | Shortcut card: hold ⌘ for 0.5 s | Round 2's tap was too easy to trigger; now ⌘ held alone for half a second shows the card, which stays up after release. A tap of ⌘, Esc, a click outside or a row click closes it. | Ben |
| 2026-10-27 | Setting a countdown starts the timer | `AppModel.setTargetDuration` starts the timer if it is not running; the deck's own pdfpc duration keeps SPEC §6.7's first-advance start. | Ben; the pdfpc exception is Fable, provisional |
| 2026-10-27 | Ink does not fade | Strokes stay until C or the next build (page change already cleared them). Implemented as `Presentation.ephemeralInkLifetime = nil`; the mode stays `.ephemeral` so persistent (sidecar) ink in M5 keeps its meaning. SPEC §8 updated. | Ben |
| 2026-10-27 | Chooser and presenter are separate windows | Like iWork: `WelcomeWindow` (720×600, resizable, scrollable content so the title never crops) and `PresenterWindow`, which fills the chooser's screen when a deck opens and hides when it closes. Closing the presenter closes the deck; closing the chooser quits. The presenter window no longer autosaves its frame. | Ben |
| 2026-10-27 | Native title bar, not a centred one | AppKit on macOS 26 puts a toolbar-less window's title at the leading edge (the self-test's `-titlebar` probe measured it at 148 of 1512 pt) and `NSWindow` has no alignment API. A drawn, centred title strip was tried and reverted the same day: Ben prefers native Mac behaviour, which here means the real proxy icon (drag, ⌘-click path menu), the inactive-window dimming, and whatever Apple does next. Both windows use `title` and `representedURL` and nothing else. | Ben |
| 2026-10-27 | Notes vs Contents is sticky | Decided once per open: contents if the deck has an outline and the first slide has no notes, else notes; after that only the headings (or writing a note) change it. Replaces round 2's per-frame fallback. | Ben |
| 2026-10-27 | Overview selection more prominent | 6 pt accent stroke with a glow and an accent-coloured label on the selected frame; the committed frame keeps its green 3 pt stroke. | Ben |
| 2026-10-27 | No links on the next-slide preview | `SurfaceController` passes link rects only to the audience and current surfaces, so the preview no longer shows a pointing-hand cursor. | Ben |
| 2026-10-27 | Overview jumps directly, no private browse | Ben: "the behavior that freezes the slide for the audience [is] awkward. Instead just make it so that if I click a slide, that one appears as the current slide immediately." Clicks on frames, outline entries and search hits now `goToPage` (history pushed once) and close the overview; arrows move a view-only cursor; Return jumps to it; Esc closes. SPEC §6.3 and §4.4 updated; the browse commands remain in PresenterProtocol and the reducer for later platforms. | Ben |
| 2026-10-27 | Overview stays open after a jump; build and notes icons | Ben: "don't close overview upon new slide click. Tab toggles mode." A click, Return, an outline entry or a search hit jumps and the overview stays until Tab or Esc; the cursor follows the jump. Each frame cell shows a stack icon with the build count beside the label when it has more than one build, and a notes icon at the right when any of its pages has a note. | Ben |
| 2026-10-27 | Present and Swap buttons in the status bar | Ben tried a TV over AirPlay in mirroring mode and could not find how to send only the slides. The status bar's right region now has Present (⌥⌘P) / End and Swap displays (⌥⌘D) buttons next to the LIVE pill, with tooltips that say to use the TV as a separate display rather than mirroring; Swap is dimmed without a second display. Icons only when the bar is narrow. | Ben |
| 2026-10-27 | ⌘D swaps displays | ⌥⌘D is macOS's Hide/Show Dock shortcut (Ben). ⌘D was free. SPEC §6.5 updated. | Ben |
| 2026-10-27 | C clears the drawing and turns Laser and Draw off | One key to get back to plain navigation (Ben). The Clear button and menu item do the same. | Ben |
| 2026-10-27 | Presenting state lives on the Present button | The LIVE / NOT PRESENTING pill and the REHEARSAL tag are gone; the Present button reads Live or Rehearsal, lit green, while presenting, and ends it when clicked. FROZEN / BLACK / WHITE keep their pill since they are audience modes, not presenting state. | Ben |
| 2026-10-27 | Overview: no glow, orange audience ring, same current-slide geometry, two columns, section dividers | Ben liked the thick blue cursor but not the haze (shadow removed). The frame the audience sees is ringed orange, the FROZEN colour, and follows the frozen page when frozen. The overview keeps the current slide where the presenter layout puts it (shared split fraction) and replaces the right column with search plus a two-column grid; the outline sidebar became titled dividers between the frames of each section, grouped by SPEC §4.4's current-entry rule, with subsections indented. | Ben |
| 2026-10-27 | No section dividers in the overview | Decks with one frame per section left every other grid cell empty (Ben: "the single-slide sections are awkward"). The outline stays available in the notes pane's Contents list. | Ben |
| 2026-10-27 | Shortcut card on ⌘/ and ?, not a ⌘ hold | Holding ⌘ then ⌘-Tab showed the card over the app switcher: macOS never delivers ⌘-Tab to the app and keeps it active while the switcher is up, so no app can tell a plain hold from one the system has claimed; the same applies to ⌘-Space and other system chords. Modifier-only triggers are an iPadOS convention the system handles; the Mac convention is an explicit key and a Help menu item. So: Help ▸ Keyboard Shortcuts (⌘/), plus ? as the widely used alias; Esc, a click outside, a row click or the app going to the background closes it. The Settings toggle for the hold is gone. | Ben asked for a best-practice fix; the key choice is Fable |
| 2026-10-27 | Notes editing removed for now | Ben: too easy to think notes are being saved when they come from a LaTeX workflow; the sidecar still loads any user notes it already holds. SPEC §5.2 updated; ⌘E is unbound. | Ben |
| 2026-10-27 | Overview is a presenting mode | Keys keep their meaning in the overview (→, Space, digits, ⇧→ …) and the grid follows the current frame (blue) and, when frozen, the audience's (orange); clicks jump. The view-only cursor from the previous day is gone. An Overview button at the top right of the right column enters and stays lit in the mode; Tab still toggles. | Ben |

| 2026-10-27 | Contents list hides the frame number of shadowed entries | A section whose first subsection starts on the same page can never be the current part, so its frame number is not shown (it is still clickable). | Ben |
| 2026-10-27 | First Esc shows its state on the Present button, not in a banner | Ben: the teal banner felt un-Mac-like.
